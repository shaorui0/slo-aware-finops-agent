## Why

README 讲了 agent 做什么，但没有把它放回读者熟悉的参照系：一个 SRE 平时手工做 requests 降配的六步流程。读者看不出哪一步原样保留、哪一步换成了代码、模型具体接手了哪一步，于是容易问出「这不就是个脚本吗」，而 README 里没有正面回答。

## What Changes

- README 在「AWS 已经做了什么」之后新增一节「传统降配流程和这个 agent 差在哪」：
  - 一张对照表：传统六步（归属、观察、分析、算账、执行、核实）各自对应 agent 的哪个环节、由谁做（代码 / 模型 / 人）、变了什么。
  - 一张三方对比：纯人工、人加脚本、这个 agent。说清楚大部分改进来自规则和工程纪律，模型只接手「把证据讲成人话」这一格。
  - 三条要点：降配是安全问题不是算术问题；判定交给代码、解释交给模型；可信度靠预注册评估和事后核实。
- 只写仓库里已有的东西；不改代码。
