# 0037 修预注册世界暴露的漏检

- 契约里没有「趋势」，agent 的四个条件就全部对着「窗口最大值」。一个线性爬升的内存，推荐 = 最大值 ×1.2，一周后被追上，A–D 全 PASS。规则缺一个维度，不是实现错。
- 趋势守卫的取舍：每日最大值做最小二乘，外推 14 天，要求 R² ≥ 0.6 且涨幅 ≥ 10% 才触发。不设这两个门槛，昼夜与周周期的噪声会让每个服务都被拦。阈值是读着失败设的，没有独立标定，灰色地带没测过。
- 只对内存开，cpu 不开：内存不可压缩，泄漏的后果是 OOMKilled；cpu 可压缩，B 已有 throttling 守卫；cpu 每日最大值被周周期支配，两周窗口相位不同就拟合出假斜率，误报面比内存大。代码按配置走，cpu 可以加进 `trend_resources`。
- 趋势证据只在触发时出现。第一版每条内存决策都加两条证据，结果报告的人话标签表（`report.py`，不在这个 change 范围）和证据落地检查都挂了。触发才加，与批任务的 job 行同理，既少打扰又不动别人的文件。代价：触发时这两行暂时显示「（未标注）」，要维护者补标签规则。
- 趋势的代码路径一开始就踩坑：逐小时序列是字节，没乘 GiB 的缩放，斜率算出 1.2 亿。单测用 fake 的 GiB 数据才抓到，说明「每个数字都有单位」要有测试盯着。
- sidecar：容器名在同一轮早先的查询里就知道了，只是没用在用量查询上。选择器加 `container="<name>"`；没有这个标签就不加，行为与以前相同。
- 定价通道：`--nodes-from` 只读 `nodes.min/max`，世界的 `pricing` 没传进来，所以金额偏一半。这是输入通道不匹配，不是装箱错。按键覆盖，缺省回落默认牌价。
- 修完以后，第一个预注册世界 verdict_accuracy 0.90 → 1.0，unsafe_allow 1 → 0。这个数字不能当泛化证据：失败驱动了修复，世界已经被污染。要证明泛化，要另一个在修复前冻结的世界。
- route-quote 没修：p99 ×1.3 的契约规则和「按尖峰定容」的 expect 不一致，是契约问题，不是 agent 缺陷。如果为了一个区间把推荐改成 max(p99×1.3, p99.9×…)，会改基础世界里已验证的推荐值。
- session-store/memory 现在判 DENY，但推荐值仍是 2.9375，离 expect 的区间 [3.3, 3.9] 还有差距。区间只给 ALLOW / REQUIRE_APPROVAL 计分，所以 request_in_range 漏掉了这个差距：DENY 是对的，数值不对没人看。
- request_in_range 的分母在变：session-store/memory 改判 DENY 退出分母，edge-gateway/memory 从 NOOP 变 ALLOW 进入分母。0.7692 → 0.9231 不是 10/13 → 12/13 的纯进步，要连着分母一起看。
- 重录盒带踩到一个意外：夹具里写入的 12 位十六进制短键恰好全是数字，仓库的泄漏扫描把它当账号号。不能改扫描器（不在范围），只能让提示词变一下，整批重录。教训：夹具里别原样写哈希前缀，或者写更长或带分隔。
- 盒带不能 rm：旧的 88 个 git mv 到 archive，两轮废弃的重录放 intermediate，MANIFEST 说明每一批为什么存在。
