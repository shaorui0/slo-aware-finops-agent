# c0041 传统降配流程对照

- agent 没有发明新的降配方法论，只是把手工六步重新分工：能写成规则的给代码，讲给人听的给模型，执行权留给人。放回这个参照系，读者才看得出模型到底接手了哪一格。
- 三方对比（纯人工 / 人加脚本 / agent）比两方对比诚实：两方对比会把「写成代码」带来的好处算到模型头上。
- 「这不就是脚本吗」的正面回答是：判定层就是脚本，故意的。模型的位置是最后一公里，把证据讲成负责人能读懂的提案。
- 传统流程里最常被跳过的两步是算账（装箱）和核实，正好是 agent 补得最实的两步。
