# c0036 第二个预注册世界：修复之前冻结

- 用来发现 bug 的世界不能再用来度量修复。第一个世界已经被评过、被「看过失败」，修复后再评它，分数含有教学成分。所以在修复之前写第二个世界，冻结，之后只评一次。
- 盲写才有意义：不读评估结果、不读 agent 代码与策略配置，expect 只从 SRE 判断加契约明文推出。唯一的漏洞是 git log 标题里带了一行聚合指标，已在证据里如实记录。盲写协议本身要被记录，否则「盲」没法被检查。
- 契约公式和 SRE 判断会打架：p99 看不见每周一小时的峰值，窗口最大值会把已经消退的内存高点当成需求，线性增长的 cpu 今天够、两周后不够。这类条目 request_range 服从契约，标 `judgment_conflict: true`，在 why 里写分歧，不替契约改答案。
- 难例的共同点是「单一统计量不够」：p99、窗口最大值、有效天数、有没有 slo 序列。每一个单独看都合理，合起来才暴露问题。末尾缺 7 天数据但有效天数仍有 21，是最典型的一个。
- 燃烧率低于 1 不等于健康：剩余预算只有 10% 时，任何一次小事故都会破 SLO。只查燃烧率的实现会放行。
- 不写 realizable 区间：first-fit decreasing 的排序键不同，节点数可以差 1。把实现细节预注册进答案，会让考卷在测实现而不是测判断。
- 生成器只做加法（新增 cpu trend），基础世界序列的 sha256 由测试钉死。
