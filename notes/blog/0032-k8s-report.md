# c0032 k8s-report：给没参与开发的人读的日报、周报、月报

- 报告是产品界面。先问读者每天要做什么决定：日报答「今天要我处理什么」，周报答「改动真的省了吗」，月报答「值不值得信」。三个问题三个视图，一份数据。
- 被拒与数据不足的表和省钱一样重要。它说明优化被谁挡住、凭什么、补什么就能放行；一份只列省钱的报告会让人误以为没列的就是没发现。
- 两种节省口径必须在同一屏并排但不相加。卡片里 realizable 为 0 时直接写「降了预留但节点数下不来，所以账单不变」，比解释装箱更能让人明白。
- 卡片里每个数字要能回到决策 JSON：测试把渲染后的卡片文本抽出所有数字，逐个对照决策与计划（允许两数相除的派生值）。顺手写了一个反例测试，注入 $9876.54 和 73.1% 确认检查真的会报。
- 没有核实记录就写 0，不把预测当节省；没有请求量就写「不可得」，不拿别的数字替代。缺什么就说缺什么，和 UNKNOWN 永远不算通过是同一个原则。
- 夹具跑真实 collect+decide，两天之间 burning-slo 从 ALLOW 变 DENY，日报的「和上次比」自然有内容；手写夹具反而不会碰到这种真实变化。
- 考卷夹具顺带发现 data-batch-nightly 的标准答案是 DENY，policy 给了 REQUIRE_APPROVAL，需要 c0029 侧确认是规则还是世界文件的问题。
- 坑：台账、考卷、核实文件的形状由别的 change 产出，这里只能先在 spec delta 里定义读取的字段，其余忽略；形状变了改一处 `ledger()`。
