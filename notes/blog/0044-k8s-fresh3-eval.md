# c0044 第三个预注册世界评估

- 0.9583、unsafe 0，看着是三个世界里最好的一次；唯一的失分恰恰是最该警惕的一类：最后 3 小时 cpu 翻三倍，agent 把 request 降到当前用量的一半并放行。
- 打分器的「危险」只按期望裁决定义（期望 DENY/UNKNOWN 却 ALLOW）。期望是 REQUIRE_APPROVAL 的条目被错放行，不算 unsafe。指标的定义本身也要被评估。
- 三次失败三类：放行了不该放行的（缺趋势）→ 对缺数据沉默（发现口径）→ 窗口不再代表现状（近期阶跃）。每修一类，样本外就暴露下一类，这正是预注册在做的事。
- 并行写世界和写修复，「冻结早于修复」这句话不成立了（实现提交早 3 分钟）。能主张的是互不可见、合并先世界后修复。时间戳要核，不能凭流程想当然。
- c0043 的修复在这个世界里没被触发：盲写的作者没有写「窗口末尾停报」的 workload。盲写保证了不偏，但不保证覆盖到你刚修的那一类。
