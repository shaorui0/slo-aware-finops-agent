c0028 合成 K8s 世界报告

改了什么

  • testenv/k8s_world.yaml：21 天、6 节点、9 个 workload，cpu 与 memory 各有 expect，另有 8 条 traps。
  • testenv/k8s_world.py：确定性生成器、load(as_of=)、场景叠加。
  • testenv/metrics_server.py：--world k8s、--as-of；默认 AWS 世界不变，原有测试全绿。
  • testenv/k8s_scenarios/drift_day3.yaml：第 3 天场景，api-steady 最后一天负载 +60%。
  • testenv/test_k8s_world.py：23 个测试。

为什么

后续的推荐器、策略引擎、执行与评估都要有一份标准答案已知的数据。先把世界做出来，几条线才能并行。

世界一览

api-steady 平均 15%，无峰 ALLOW，0.225–0.275 ALLOW，1.0–1.25 GiB

装箱事实

自带 first-fit decreasing（四种排序键结果一致）：基线 6 个节点；只应用 api-steady 的 cpu 推荐降到 5 个，约 140 美元每月；只应用 packing-trap 的 cpu 推荐仍是 6 个，realizable 为 0。

契约变更请求

  1. 新增 container_cpu_usage_cores（gauge）：子集不支持子查询。
  2. rate 窗口至少 [10m]：[5m] 在 5 分钟网格上为空。
  3. NOOP 规则先于 OOM 守卫命中：mem-near-oom 的 memory 无法在推荐值低于当前值时成为 DENY，建议调整判定顺序。
  4. batch 的「100%」按单线程满载（request 的 50%）解释；api-tidal 的峰值用窄尖峰。
